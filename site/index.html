Architecture

證據先行，而不是把既有表單硬套到另一家醫院

每一層都保留清楚的責任邊界；傳輸成功不等於規則已驗證。

01

來源擷取

保存來源 URI、原始 byte SHA-256、文字 SHA-256 與不可變快取。

02

精確定位

產生穩定 span ID，以及 line、char、byte locator 與短 context。

03

人工審核

人員選取證據並定義流程或需求；工具重新核對所有雜湊。

04

Adapter 執行

文件與網站 adapter 只消費已審核契約，危險動作維持人工控制。

KMUH default

高醫流程是事件分支，不是固定線性序列

新案可能反覆補件與複審；核准後可分別提出變更、持續審查、安全事件或不遵從通報， 最後才可能結案、終止或撤案。舊有 KFSYSCC SF 表單仍保留在相容層，但不會被冒名當作 KMUH 表單。

目前的證據狀態

契約先宣告 SOP、表單集合、流程與候選需求。官方文件尚未成功取回以前， locator 保持 needs_retrieval；取回後也只會先升為 needs_mapping。

Human-login-gated browser MCP

登入交給人，頁面 mapping 才交給工具

不接觸密碼

MCP 只 attach 到人類已登入的專用 Chrome profile，不接收或保存 KMUH 帳密。

不保存案件內容

頁面 mapping 保存 selector、雜湊識別與風險分類，不保存欄位值、本文或原始 label。

沒有送出工具

submit、核准、撤案、終止及刪除不在 MCP surface；草稿寫入另有雙重開關。

拒絕 stale mapping

live fingerprint、control ID 或風險分類不同時立即拒絕，要求重新人工檢閱。

Quick start

先看就緒度，再取回來源與映射證據

terminal
uv sync --group dev
uv run irb-contract show
uv run irb-contract requirements \
  --submission-type new \
  --review-track general \
  --workflow-event submit_new

# Chrome bridge 只檢查人類已登入的既有 session
uv run irb-contract browser-status

詳細指令、安全界線與 reverse SSH 設定請見 繁體中文 README 與 KMUH Browser MCP 指南。
